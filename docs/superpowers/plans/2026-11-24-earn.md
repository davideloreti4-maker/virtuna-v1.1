# Earn: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. One task per
> implementer, a failing test first for every behaviour, a review after each task.

**Goal:** a page `/earn` under the new look: the creator's link, what it has earned, a card to share,
how it works, and the creators who joined; and the recording that makes the number true: one row per
payment of a referred creator. Spec: `docs/superpowers/specs/2026-11-24-earn-design.md` (read it first;
it wins over this plan where they differ, and the controller's `rulings.md` wins over both). Facts with
file and line: `.scratch/next-look/part7/earn/seam-map.md`.

**Shape:** one new table `referral_earnings`; a pure module `src/lib/earn/` (the rule, statuses, sums,
words); one new case in the payment webhook; one read route `GET /api/earn`; the page and its parts in
`src/components/earn-next/`; a row in the sidebar and on the You page.

**Stack:** Next.js 16, TypeScript, Supabase (row level security), TanStack Query, Vitest, Tailwind v4.

## Global constraints (every task)

- Everything is behind `NEW_LOOK_ENABLED` (`src/lib/flags/new-look.ts`). Flag off: `/earn` is not found,
  `GET /api/earn` answers 404, nothing renders, and the app is exactly as before, the Settings tab
  "Referrals" and its Pro gate included. Never change an existing `@theme` value.
- The ONE thing that also runs with the flag off is the webhook's new case: a payment is a payment
  whatever look the app shows. It must never throw, never change what the webhook answers, and never
  touch the other cases.
- A failing test first for every behaviour. Stand-ins only at I/O boundaries (the database client,
  `fetch`, the clock, `navigator`) and for the build-time flag.
- No commit, stash or push. No `.env*` reads. No dev server, build, network, model call or database
  query. The repository is public: made-up names, codes and ids only.
- Money is whole cents in the code and the database, never a float sum. One function turns cents into
  words.
- No other person's name, email, handle or id ever leaves the server for a referrer: creators are
  numbered ("Creator 1") in the order they joined.
- Words on screen are exactly the ones in this plan. Plain words; "chat", never "thread".
- New-look styling rules of `CLAUDE.md` hold (tokens, `shadow-[var(--shadow-float)]`, ink buttons).
- Vitest needs `NODE_OPTIONS=--no-experimental-webstorage`. Never run vitest with `-u`.

## Constants and contracts (shared by both tasks)

`src/lib/earn/earn.ts` (pure, no React, no server imports):

```ts
export const EARN_RATE_PCT = 50;                 // the referrer's share of a payment
export const EARN_MONTHS: number | null = null;  // null: for as long as they pay; a number: payments in the first N months after joining
export const EARN_PENDING_DAYS = 30;             // a share is "ready" this long after its payment
export const EARN_PAYOUT_MIN_CENTS = 5000;       // paid out from $50
export type EarningStatus = "pending" | "ready" | "paid" | "void";

/** What `GET /api/earn` answers. */
export interface EarnPage {
  link: string;                 // https://<app>/?ref=<CODE>
  code: string;
  name: string | null;          // the creator's own display name, for the share card
  joined: number;               // creators who signed up through the link
  earnedCents: number;          // pending + ready + paid (never void)
  pendingCents: number;
  readyCents: number;
  paidCents: number;
  creators: { n: number; joinedAt: string; paying: boolean; earnedCents: number }[]; // newest first, at most 50
}
```

Rules, each a pure function with tests:

- `earnedCentsOf(paidCents)`: `floor(paidCents * EARN_RATE_PCT / 100)`; 0 or less, or not a whole
  number, gives 0.
- `countsFor(joinedAt, paidAt)`: true when `EARN_MONTHS` is null; else when `paidAt` is before
  `joinedAt` plus that many calendar months.
- `statusOf(row, now)`: the stored `paid` and `void` stay; else `ready` when `paid_at` is at least
  `EARN_PENDING_DAYS` old, else `pending`.
- `sumsOf(rows, now)`: the four cents totals of `EarnPage`.
- `paidCentsOf(amount)`: the payment provider gives an amount in the currency's main unit as a number
  or a numeric string (`49`, `"49.00"`, `49.5`): whole cents, rounded; anything else null.

Words, `src/lib/earn/earn-words.ts` (pure):

| Function / string | Result |
|---|---|
| `moneyWord(cents)` | `$0`, `$58.80`, `$1,240`, `$1,240.50` (no ".00"; two places otherwise) |
| `promise()` | `Earn 50% of everything they pay, for as long as they stay.` or, with `EARN_MONTHS = 12`, `Earn 50% of everything they pay in their first 12 months.` |
| `splitLine(page)` | `$39.20 ready · $19.60 pending` (a zero part is left out; `$20 paid out` is added when there is one); null when nothing was earned |
| `joinedLine(n)` | `0 creators joined through your link`, `1 creator joined through your link`, `3 creators joined through your link` |
| `howItWorks()` | three lines: `Share your link or the card.` / `A creator signs up within 30 days of opening it.` / `You earn 50% of each payment they make. Paid out monthly once you reach $50.` (rate, months and minimum from the constants) |
| `creatorLine(c)` | `Joined Nov 3 · Paying` or `Joined Nov 3` |

Fixed strings: page and row name `Earn`; `earned` beside the number; card titles `Get paid for creators
you bring`, `How it works`, `Your creators`; `Creator 1`; buttons `Copy`, `Copied`, `Share`, `Save
image`; on the share card `YOU EARN`, `50%`, `SHARED BY`; the share text `Simulate your videos before
you post them. Try Maven:`; errors `Couldn't load Earn. Try again.` with `Try again`.

- [ ] **The migration** (additive, safe to run twice; written here, applied by the controller only):

```sql
create table if not exists public.referral_earnings (
  id uuid primary key default gen_random_uuid(),
  referrer_user_id uuid not null references auth.users(id) on delete cascade,
  referred_user_id uuid not null references auth.users(id) on delete cascade,
  payment_id text not null check (char_length(payment_id) between 1 and 200),
  paid_cents integer not null check (paid_cents > 0),
  currency text not null default 'usd' check (char_length(currency) between 3 and 8),
  rate_pct smallint not null check (rate_pct between 1 and 100),
  earned_cents integer not null check (earned_cents >= 0),
  paid_at timestamptz not null,
  status text not null default 'pending' check (status in ('pending','paid','void')),
  paid_out_at timestamptz,
  created_at timestamptz not null default now(),
  check (referrer_user_id <> referred_user_id)
);
create unique index if not exists referral_earnings_one_per_payment on public.referral_earnings (payment_id);
create index if not exists referral_earnings_referrer on public.referral_earnings (referrer_user_id, paid_at desc);
alter table public.referral_earnings enable row level security;
-- one policy, for select, the referrer's own rows, in the (select auth.uid()) form; guarded by a lookup. No policy for writing.
```

  ("ready" is not stored: it is `pending` that is 30 days old.) Model the guard and the policy on
  `supabase/migrations/20261124130606_piece_posts.sql`. A test reads the SQL and proves the code's limits
  against it (the pattern of `src/lib/posted/__tests__/migration.test.ts`).
- [ ] **The rules and the words** above, tests first: every branch and boundary (29 days 23 h and 30
  days; `EARN_MONTHS` null and 12; amounts `49`, `"49.00"`, `0`, `-1`, `"abc"`, `49.999`; odd cents;
  one and many creators; every part of `splitLine`).
- [ ] **`ensureReferralCode(client, userId)`** in `src/lib/referral/ensure-code.ts`: the loop that is in
  `src/app/(app)/settings/page.tsx` today (create on first view, retry on a taken code), moved, with
  tests; the Settings page calls it and behaves exactly as before.
- [ ] **`record-payment.ts`**: `recordPayment(client, payment)` where `payment` is what the webhook
  could read: `{ paymentId, payerUserId, amount, currency, paidAt }`. In order: no payment id, no payer
  or no whole-cent amount above 0 → nothing; the payer's referrer = the EARLIEST `referral_clicks` row
  with `referred_user_id = payer`; none, or the payer themselves → nothing; `countsFor(joined, paidAt)`
  false → nothing; else insert one row (`earned_cents = earnedCentsOf(paid)`, `rate_pct =
  EARN_RATE_PCT`), and a second delivery of the same payment (the unique index, error 23505) is a quiet
  no-op. It returns what it did (`"recorded" | "duplicate" | "not_referred" | "ignored"`) and never
  throws: a database error is logged without ids and returned as `"failed"`.
- [ ] **The webhook's new case** (`src/app/api/webhooks/whop/route.ts`): the event "a payment succeeded"
  (`payment.succeeded`, through the route's own `normalizeEventName`, so the underscore spelling too).
  The payer is the app's user: `resolveUserId(data)` as the other cases use it, else the
  `user_subscriptions` row whose `whop_membership_id` is the payment's membership id, else whose
  `whop_user_id` is the payment's user id. The amount is `final_amount` (see `paidCentsOf`), the id is
  the payment's `id`, the time its `paid_at` or `created_at` (seconds or an ISO text), else now. Call
  `recordPayment` with the service client the route already has; whatever it returns, the webhook
  answers as it does today. Tests with the payload shapes the route's existing tests use, plus a payment:
  a referred payer records one row; twice records one; a payer nobody referred records none; a payer who
  is the referrer records none; a malformed amount records none; the other cases' tests stay green
  untouched.
- [ ] **`earn-read.ts` and `GET /api/earn`**: 404 with the flag off and for a funnel visitor
  (`isSealedVisitor`), 401 signed out; else `EarnPage` for the caller: the code (made on first view, for
  ANY account), the link (`NEXT_PUBLIC_APP_URL`, as the Settings page builds it), `joined` = the
  caller's `referral_clicks` rows, the sums, and the creators (numbered by when they joined, 1 = first;
  listed newest first; `paying` = has at least one row that is not void). Never a referred person's id,
  name or email in the answer: a test asserts the answer's keys.
