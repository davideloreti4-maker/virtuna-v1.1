# The Worker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A take uploaded from the app comes back analysed (two copies, its words timed to the sound, its pauses, where the face is, its loudness), and an edit becomes an MP4 with progress that survives a reload. Part 2 of the design.

**Architecture:** One Modal app with two images. The *media* image (Python, ffmpeg, the speech and face models) analyses a take; the *render* image (Node, the renderer's Chrome, the film bundled from this repo) renders films and stills. Each pipeline is a plain function from files to files and facts, with no storage or database inside it, so each is proved on the owner's real take before any key exists. A thin outer layer fetches from R2, runs a pipeline, stores the results and writes progress into a job row. The app writes the job row, calls the worker's one web address, and reads the row back; it never streams media and holds no Modal token.

**Tech Stack:** Modal 1.6.3 (Python 3.12), ffmpeg (Debian 12), faster-whisper and WhisperX's aligner, Silero VAD, MediaPipe Face Landmarker, boto3 for R2; Node 22, `@remotion/renderer` 4.0.545 and the film bundled by `@remotion/bundler` 4.0.545; Supabase (Postgres, RLS); Next 16 routes; `aws4fetch` to sign R2 addresses in the app.

**Spec:** `docs/superpowers/specs/2026-11-19-edit-design.md` §7 (upload analysis), §10 (the render), §11 tests 3, 5, 6, §12 part 2. The edit it renders: `src/lib/edit/`; the film: `src/edit/film/`.

**Status: written 2026-11-20.** Like the kit plan, it names the tasks, files, interfaces and how each is proved. Each task's code is written test first when the task is built, with the tool's documentation open: no engine, Modal or model call is written from memory.

## Global Constraints

- Nothing in the product is named after the engine (N9). The Modal app is `maven-edit-worker`; folders are `worker/` and `src/lib/edit/worker/`.
- Facts about a file are measured once on the worker and stored (N5). Never a browser's number, never the agent's.
- Nothing is placed from a transcript alone (N3): every word's time comes from the aligner, on the sound.
- What is posted is never a stand-in: a render where the colour pass cannot run fails (design §13, "Left open").
- `@remotion/renderer` and `@remotion/bundler` run only in the render image and in scripts, never in a Next route or anything Vercel builds.
- Every engine package stays pinned to exactly `4.0.545`, the same version in the app and the image.
- `licenseKey: "free-license"` on every render and still (design §10).
- Secrets are never read, printed or passed through the chat. The owner puts them in `.env.local` and in the Modal secret with scripts he runs himself (`! bash …`). Never read or list `.env*`; never read `~/.modal.toml`; check the Modal login only with `modal profile list`.
- The owner's takes stay outside git (`.scratch/media/`). Anything sent to Modal goes to his own workspace only.
- Launch Modal runs one at a time ("App create rate limit exceeded" with four at once, 2026-11-12). Every function has a `timeout`; cores are requested and limited to the same number, so a run cannot cost more than its timeout at that size.
- Tests exercise the real code. Mocks only at boundaries that cannot run in the suite (R2, Modal, ElevenLabs over the network); those are proved by a real run instead, written down in the task.
- Commits stay local on `feat/edit`, made with `git -c core.hooksPath=/dev/null commit`. Never push.
