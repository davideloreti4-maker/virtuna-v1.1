# The Kit and the Film Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Draw an edit: the kit's parts and the film as React components, a page that plays an edit in the app, and a test that the preview and the rendered picture are the same.

**Architecture:** The film is one component that takes an edit and the addresses of its files, and draws everything from `src/lib/edit/derive.ts`. Each run of footage is one piece of media inside a transition series; every mark, item and caption is placed on the film from `placed()` and `runWords()`. The same component runs in the Player in the app and in the renderer, so what is seen is what is posted (N1). No part writes its own timing arithmetic.

**Tech Stack:** Remotion 4.0.545 (`remotion`, `@remotion/player`, `@remotion/media`, `@remotion/transitions`, `@remotion/captions`, `@remotion/effects`, `@remotion/layout-utils`, `@remotion/fonts`; `@remotion/renderer` and `@remotion/bundler` as dev dependencies, for stills in tests only), React 19, Next 16, vitest 4, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-19-edit-design.md` §3 (rules), §4 (what is used), §6 (the kit), §9 (the Player), §11 test 4. The document layer it draws: `src/lib/edit/` and `docs/superpowers/plans/2026-11-19-edit-document.md`.

**Status: written 2026-11-19, not started.** This plan names the tasks, the files, the interfaces and how each is proved. The code of each task is written test first when the task is built, with the engine's packages installed and its documentation open: engine calls are not written from memory.

## Global Constraints

- Every engine package is pinned to exactly `4.0.545`, all the same version. After `pnpm add`, lockfile hunks that are not about the added packages are restored.
- `@remotion/renderer` and `@remotion/bundler` are dev dependencies and are imported only by scripts and tests. Never by a Next route, a server action or anything Vercel builds into a function.
- Nothing in the product is named after the engine (N9): folders are `src/edit/film/` and `src/edit/player/`; no file, export or route carries its name.
- Parts are styled inline, without Tailwind and without the app's CSS (X7): the film must look the same in the app and in the renderer's bare page.
- Parts animate from the current frame only (`interpolate`, `spring`): no CSS transitions or animations, no timers, no `Math.random`, no `Date`.
- All timing comes from `derive.ts`: `layout`, `placed`, `runWords`, `framingAt`, `momentOf`, `lookOf`. A part gets its frames as props.
- Only what a phone can show is in the kit (N1): no feature that needs HTML-in-canvas (motion blur, effects on text, the twelve transitions that need it).
- One colour pass per run, and decoded frames no larger than shown (N6).
- Every font and sound in the kit has its licence written beside it (N7). No licence key is set by an agent; `acknowledgeRemotionLicense` and `licenseKey` are the owner's to set.
- Tests exercise the real code. The test take is the owner's and stays outside git: `.scratch/media/`.
- Commits stay local on `feat/edit`, made with `git -c core.hooksPath=/dev/null commit`. Never push. Never read or list `.env*`.

## What the engine was found to do (2026-11-19, run in the old trial project)

- A start between two source frames is accepted; the picture is the source frame on screen at that moment.
- A transition may not be longer than the sequence before or after it; a sequence fading in and out at once is drawn.
- A volume given as a function of the frame, above 1, at another playback rate, renders. Whether it is louder is not yet measured (Task 3 measures it).

## File Structure

| File | Responsibility |
|---|---|
| `src/edit/film/props.ts` | What the film is given: the edit and the address of each file. A zod schema, because the renderer passes them as JSON. |
| `src/edit/film/Footage.tsx` | One run of footage: a clip or a picture, framed, at its speed, volume and look, frame by frame from `derive.ts`. |
| `src/edit/film/parts/Title.tsx`, `Callout.tsx`, `Progress.tsx`, `Cutaway.tsx`, `Sound.tsx` | One component per part of `src/lib/edit/parts.ts`. Each takes its typed settings and its frames. |
| `src/edit/film/parts/index.ts` | The kit: part name to component, and the layer each kind is drawn on. |
| `src/edit/film/Captions.tsx` | The captions of one run: pages from `runWords`, in one of four looks. |
| `src/edit/film/fonts.ts` | The kit's three typefaces, loaded from files of our own. |
| `src/edit/film/Film.tsx` | The film: the runs in a transition series, and above them every placed thing and the captions. `filmSize(edit)` gives its length and size. |
| `src/edit/film/root.tsx` | The entry the renderer bundles. Used by scripts and tests only. |
| `src/edit/player/EditPlayer.tsx` | The Player in the app: a client component that plays an edit. |
| `src/app/dev-edit/page.tsx`, `src/app/dev-edit/dev-edit.tsx`, `src/app/api/dev-edit/media/[...path]/route.ts` | A page that plays a hand-written edit, and the route that serves its files from `.scratch/media/`. Both 404 in production, like the repo's `/dev-shots`. The route sits under `/api/` because the app's session guard lets `/api/` through untouched. |
| `scripts/edit-still.mts` | Renders stills of an edit with the renderer, for the test and for looking. |
| `tests/edit/preview-vs-render.test.ts` | Test 4: the Player's picture against the rendered still, at every cut and at chosen frames, in Chromium and WebKit. |

### Task 1: The engine's packages, and the licences written down

- [x] `pnpm add --save-exact` the eight runtime packages at `4.0.545`; `pnpm add -D --save-exact` the renderer and the bundler. Restore lockfile hunks that are not about them. (Done 2026-11-19. Each `pnpm add` bumped `react-grab`, `@react-grab/cli` and `bippy`; their old blocks were put back, and against the lockfile before, no package that was there has changed. `@remotion/media` brings its own `zod@4.6.7` beside the app's 4.3.6: never hand one of our schemas to the engine.)
- [x] `docs/edit/LICENCES.md`: the engine's licence as it applies (free for a company of up to three people; what changes above that; that the owner sets the key), and one line per font and sound as they are added.
- [x] Proved by: `pnpm exec tsc --noEmit` clean; the edit module's suite passes. **Moved to Task 7:** `pnpm build`, because nothing in the app imports the engine before the Player does.

### Task 2: What the film is given, and the fonts

- [x] `props.ts`: `FilmPropsSchema = { edit, kit, urls }`, `type FilmProps`, `addressOf(props, asset)`, `filmSize(edit)`. `kit` is where the kit's folder is served from (`/edit` in the app): a file kept in the kit (a sound, a typeface) is found under it, so only the other files need an address in `urls`.
- [x] `fonts.ts`: the three typefaces as files under `public/edit/fonts/` with their licence files; `fontFamily(font)`; `useFonts(kit, fonts)` loads what an edit uses (`fontsOf(edit)` in `derive.ts`) and holds the render until they are in.
- [x] Proved by: unit tests of `props.ts` (a file with no address is refused, naming the file) and of the fonts (every typeface an edit may name has a real font file with its open licence beside it). Not yet proved: `useFonts` itself, which needs the engine running; Task 4's stills prove it.

### Task 3: Footage

- [x] `Footage.tsx`: for one run, one piece of media over `run.fromMs` to `run.toMs` at `run.speed`. On each frame: the piece of the run that frame belongs to (`shotOn` in `derive.ts`), its framing from `framingAt(shot, momentOf(run, frame))`, its volume, its look from `lookOf` through `looks.ts` (`gradeOf`: one colour pass, or none when the look changes nothing). A picture is drawn as a picture. The sound fades over two frames where the run starts and ends, never at a cut inside the run. Built 2026-11-19 together with a first `Film.tsx` (the runs in a transition series, the six cuts), `root.tsx` and `scripts/edit-still.ts`, because footage cannot be looked at without them.
- [x] First look, 2026-11-19: six stills of a hand-written edit of the owner's take (`.scratch/media/make-demo.ts`, stills in `.scratch/stills/demo/`): the footage, a cross-fade between two runs, a punch-in at a cut inside a run and the warm look all draw as the edit says.
- [x] Framing: `zoom` scales the picture from its centre; `x` and `y` shift it by a share of the room the zoom leaves. The largest zoom a file's size allows, settled 2026-11-19 by looking at the owner's 720p take at six zooms, pixel for pixel (`.scratch/stills/zoom-sheet.png`): at zoom 1 the take is already enlarged one and a half times, and it turns visibly soft from about twice its own pixels. The kit refuses nothing here, it draws what it is told; `review` is to flag a zoom above 2 x the file's width / the stage's width (1.33 for a 720p take, 2 for 1080p).
- [x] A volume above 1 is louder, measured 2026-11-19 on the rendered sound of the demo edit at four volumes (`scripts/edit-film.ts`, `ffmpeg volumedetect`): 0.25, 0.5, 1 and 2 give a mean of -43.3, -37.3, -31.3 and -25.3 dB: 6.0 dB for every doubling, also above 1. The document keeps 0 to 2. A loud take at 2 will clip; that is `review`'s to flag.
- [x] Proved 2026-11-19, in the real renderer, on the owner's take: a run of 90 frames in one piece against the same run cut into three pieces gives byte-identical stills on all eleven frames tried, including the frames on and beside both cuts (`.scratch/media/make-proofs.ts`; stills in `.scratch/stills/whole` and `pieces`). At double speed, frames 0, 30 and 44 are byte-identical to frames 0, 60 and 88 at normal speed: a start is a moment of the file whatever the speed.
- [x] The sound of a cut inside a run, measured: the rendered sound of a run in one piece and of the same run cut into three pieces is the same file, byte for byte. And a sound part is heard on its frame: the tick of the demo edit, rendered alone, starts at 6.1667 s, which is frame 185, and lasts 0.297 s of the 0.3 asked (its last 3 ms are in its fade).
- [x] `scripts/edit-film.ts <demo.json> <out.mp4 | out.wav> ...` renders a whole edit with the real renderer: the demo edit (280 frames, 1080 x 1920, H.264 and AAC) in 30 s on this Mac, 10.9 MB; five frames taken from the file itself were looked at. It is quiet (-28.3 LUFS): levelling the sound belongs to the upload step.

### Task 4: The parts

- [x] One component per part (`parts/Title.tsx`, `Callout.tsx`, `Progress.tsx`, `Cutaway.tsx`, `Sound.tsx`), each given `PartProps` (`parts/types.ts`): its typed settings, its first frame, its frames, the frames it has already run (`skip`), whether it lasts to the film's end (`toEnd`: it then holds and does not go out), and the file it plays.
- [x] `parts/index.ts`: `KIT`, part name to component and layer. Layers, from the back: footage, sound, cutaways, call-outs, captions, titles, progress bar. Within a layer: by first frame, then by id.
- [x] Text is fitted with the engine's layout tools (a title to three lines, a call-out to one, held inside the stage).
- [x] Proved by: a test that `KIT` and `PART_IDS` are one list; stills of a demo edit with a title, a call-out, a cutaway, an end card and a progress bar, looked at on 2026-11-19 (`.scratch/stills/demo`, `demo2`). Every look of every part is among the 27 edits of Task 8, where the Player's picture and the render agree. **Not yet:** the sound has been rendered into no file that was listened to.
- [x] Type in whole pixels (sizes, line heights, places: `even` in `parts/types.ts`) and measured as it is drawn (`MEASURED_AS` in `fonts.ts`), so every browser lays a title out alike (design X32, X31).
- [x] A title is held inside the stage whatever place it is given, and a label title is fitted in the room its padding leaves: fitted to the bare box, a label of three full lines was drawn on four or five (found by the independent review, seen on six long titles, `.scratch/probe/lines-probe.ts`).
- [x] **The kit breaks its own lines** (`lines.ts`, pure and tested: `evenBreaks`, `rowsWithin`, `fitLines`, `markedWords`). Left to the browser, a long label title broke "…editors do / not want…" in Chrome and "…editors / do not want…" in WebKit, so a Safari preview could differ from the posted file, and a label of several lines had boxes that overlapped. Now a title is set on the fewest lines that let its type be as large as asked (else on three, smaller), evened out, each line drawn as measured, in a box of whole pixels; a label's lines are stacked boxes that touch. Captions get their rows the same way; a word too long for the row sets its page's type smaller; a page is held inside the stage by the tallest page of its run. A difference of under half a percent between two ways of breaking does not decide (two browsers measure a hair apart).
- [x] Words are measured without kerning and drawn with it (`MEASURED_AS` in `fonts.ts`, design X37): the sweep caught a 40-letter call-out set at 49 pixels in Chrome and 48 in WebKit, because Chrome kerns "-o" and WebKit does not (`.scratch/probe/measure-probe.ts`, `pair-probe.ts`: 54 measurements agree to 0.05 % but for that pair; with kerning off, to a hundredth of a pixel).
- [x] Every box in the film counts its padding into its width, said by the film itself (`BOXES` in `Film.tsx`): the app says so for every element on its pages and the renderer's page does not, which would have set a padded box differently in the two.
- [x] Proved on 21 edits with awkward text made through the door (`.scratch/media/make-text-probes.ts`: long titles in each look, one unbreakable word of 43 letters, marks over several words and over part of one, places at the stage's very edges, a 40-letter call-out in a corner, captions at 160 and 200 pixels with six words a page, a 34-letter word): in Chromium and in WebKit every text part is on the stage, a title on no more than three lines, and the lines and their boxes are the same in both (`.scratch/probe/text-probe.ts`; pictures looked at: `.scratch/stills/text-titles-*.jpg`, `text-captions-*.jpg`, `text-long-word.jpg`).

### Task 5: Captions

- [x] `pages.ts`: `pagesOf(words, maxWords, runFrames)`, our own paging, pure and tested (a new page when full, after a pause of twelve frames, after the end of a sentence). The engine's caption paging is not used: ours works in the frames `runWords` gives, the same frames the marks land on.
- [x] `Captions.tsx`: four looks (pill, popping word, highlighted word, plain); the word being said is shown; a stressed word is drawn stronger; a page is whole and at full strength from its first frame.
- [x] Proved by: unit tests of the paging; the popping-word look on stills, the pill and the highlighted word on the dev page (`.scratch/stills/live/sheet.jpg`), all four looks and all three typefaces among the 27 edits of Task 8.

### Task 6: The film

- [x] `Film.tsx`: a transition series with one sequence per run and the six transitions between runs; above it, once the typefaces are in, every thing from `placed()` in its layer, and each run's captions. `root.tsx` registers it for the renderer.
- [x] In a transition, the two runs' sound crosses over the shared frames, and the outgoing run's captions stop where the transition begins, so two voices and two captions are never on at once. Found by looking at the first stills.
- [x] Proved by: a hand-written edit of the owner's take (three runs, a fade, a punch-in, every part) rendered to stills and looked at, 2026-11-19. All seven transitions looked at in the Player (`.scratch/stills/cuts-1.jpg`, `cuts-2.jpg`) and equal to the render on three frames each.
- [x] The film takes nothing from the page it is shown on (`OWN` in `Film.tsx`, design X31). Found by Task 8: the app's page smoothed the film's letters thin and the renderer's page did not.
- [x] The six looks set by looking at renders of the take (`.scratch/stills/looks-final.jpg`); the first vivid and warm were not usable (design X33).
- [x] Where a browser has no WebGL 2 the look is drawn by a stand-in and the app is told (`grading.ts`, `standInOf` in `looks.ts`, design X30). Proved in such a browser: the footage is painted on the first jump into every run, with no error; and by forcing a browser to promise WebGL 2 and not give it: the film goes on with the stand-in from the second frame.

- [x] `EditPlayer.tsx`: the Player, given an edit and addresses. Props memoised; a run, a cutaway and a sound are made ready one second ahead (design X35, spec §9 "As built"); `onApproximateColour` tells the app when the looks on screen are a stand-in.
- [x] `/dev-edit` plays the hand-written edit of the owner's take (`.scratch/media/demo.json`, made by `.scratch/media/make-demo.ts`); `?demo=<name>` plays another edit in `.scratch/media/`; `?bare=1` shows the film alone at full size. Buttons send a look, a caption look and a cut through `applyOps`, and `window.__editApply` does the same for a test.
- [x] Looked at on 2026-11-19 in Chromium at 430 x 932: the first frame draws, play runs, no error in the console; one warning, the engine's licence note, which is the owner's to answer.
- [x] A change through the door, measured in Chromium at phone size: the picture has changed 24 to 33 ms after the call, the same canvas is still there, the playhead has not moved; a refused change shows its reason (`.scratch/stills/live/`).
- [x] Played through from a real tap, 280 frames: Chromium 9.40 s and WebKit 9.34 s for 9.30 s of film, no frame skipped, no footage on screen before it was painted. Without the second of lead the film stood still for 225 ms at the cutaway and 189 ms at the fade.
- [x] WebKit (Playwright's build of it, WebKit 26): the film draws, plays and runs the colour pass. An iPhone is still its own test.
- The dev server here is stopped from outside now and then (three times on the evening of 2026-11-19, each time cleanly and with nothing in its log; the cause was not found). The script says so when it is down; start it again.
- `src/app/api/dev-edit/media/` now has tests on real files (whole file, byte ranges, refusals, letting go of the file when the reader stops early). Its stream no longer uses Node's own adapter, which three times in an evening wrote into a closed stream (an uncaught exception in the dev server; never reproduced on demand, 900 aborted requests tried).
- **How to play it through again:** `pnpm exec tsx .scratch/probe/play-probe.ts` (`PROBE_BROWSER=webkit` for WebKit); the probes live outside git.
- [x] `pnpm build` with the engine imported by the app: passes (44 s, with the build's own type check), run with placeholders for the two public settings the worktree lacks. `/dev-edit` and its media route are built and answer 404 in production.
- **How to open it.** Always bound to this machine only: `NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54399 NEXT_PUBLIC_SUPABASE_ANON_KEY=placeholder pnpm exec next dev -H 127.0.0.1 --port 3040`, then `http://127.0.0.1:3040/dev-edit`. The two values are placeholders so the session guard can run in a worktree without `.env.local`; with the real file they are not needed. Without `-H 127.0.0.1` the server listens on the whole network, and the media route serves the owner's take: on 2026-11-19 it ran that way for a few minutes by mistake.

### Task 8: Preview against render (test 4)

- [x] `scripts/edit-render.ts` bundles the film once and renders stills with one browser; `scripts/edit-still.ts <demo.json> <out-dir> <frame>...` is its command for a person. It takes its 58 MB bundle away again (eighteen of them had filled a gigabyte of the temp folder).
- [x] `scripts/edit-preview-vs-render.ts <out-dir> <demo>:<frames> ...`: for each frame, the rendered still against the Player's picture in Chromium and in WebKit. Two measures: the share of pixels far apart (limit 0.4 %) and how far the colours are apart on average (limit 1.2 levels of 255 in Chromium, 2 in WebKit). It is a script with its own command and not a test in the suite, because it needs the dev server, the renderer and a take (design X34). It keeps the pictures of failing frames only.
- [x] Proved 2026-11-19 on 98 frames of 27 edits made through the door by `.scratch/media/make-variants.ts` (every look, one look on one shot, eight cuts, the caption looks and typefaces, the title and call-out looks, a fast and a slow shot, a camera move, the bar, a contained cutaway): Chromium at worst 0.25 % and 0.80 levels, WebKit 0.34 % and 1.66 levels.
- [x] Proved again after the kit took over its line breaking, on 129 frames of 53 edits (the 27, six long label titles, and 20 edits with awkward text): Chromium at worst 0.29 % and 1.05 levels, WebKit 0.34 % and 1.65 levels.
- [x] And it fails when it should: a title and a call-out one frame late are 0.5 to 2.1 % of pixels apart on their first frames; a film rendered warm and shown with no look is 3.6 levels apart while no pixel counts as far apart, which is why the colours are measured too.
- [x] What it found, each fixed: footage left black without WebGL 2; a first vivid look that was not usable; letters 7 % fuller in the posted file than in the preview; a title's third line two pixels off in WebKit.
- [x] It failed on one case after the first sweep: a long label title in WebKit (`demo-label4`, made by `.scratch/media/make-label-probes.ts`), 2 % of pixels, because the browsers broke its lines differently. That is what made the kit break its own lines (Task 4).
- [x] It starts a dev server of its own when none is running (`scripts/edit-dev-server.ts`), bound to this machine only, and stops it again.
- The scripts have a type check of their own, because the repo's leaves `scripts/` out: `pnpm exec tsc -p scripts/tsconfig.edit.json`. (Until the independent review said so, nothing had checked them; it found two missing declarations.)
- **How to run it:** the dev server as in Task 7, then `pnpm exec tsx .scratch/media/make-variants.ts` (prints the jobs) and `pnpm exec tsx scripts/edit-preview-vs-render.ts .scratch/stills/pvr <the jobs>`. Chromium here is Playwright's full browser (`channel: "chromium"`); its headless shell has no WebGL 2 and is the script's third browser, `stand-in`, on purpose. WebKit needs `pnpm exec playwright install webkit` once (done on this Mac, 300 MB).

## Done when

An edit written by hand plays on `/dev-edit` on a phone-size screen, a change made through the door shows at once, and the preview-against-render test passes in both browsers.
