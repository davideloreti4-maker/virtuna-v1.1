# You (part 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With `NEXT_PUBLIC_NEW_LOOK` on, `/you` is one page of what Maven knows about the creator (what it read from their account, seven rows in their own words, their accounts, a way to Settings), reached from a sidebar row on desktop and Home's avatar on the phone, and the five new facts on it change what hooks, ideas, script, chat and remix write.

**Architecture:** One additive migration adds five text columns to `creator_profiles`; they join the existing `GET`/`PATCH /api/profile/creator-profile`. A new read-only `GET /api/you` returns the accounts, the primary account's followers and "what Maven read". A new folder `src/components/you-next/` holds a presentational screen, its row parts, pure helpers and a container that reads through TanStack hooks in `src/hooks/queries/use-you.ts`. The writers read the facts through new roles in `PROFILE_ROLE_MAP` (one shared thin check, cap 7,200) and through remix's own creator block. Every new read of the facts is behind the build-time flag.

**Tech Stack:** Next 16, React 19, TypeScript, Tailwind v4, Supabase (session server client, RLS), TanStack Query 5, Zustand (shell store), Radix (the app's `Sheet` and `Popover`), Vitest + happy-dom + Testing Library + vitest-axe.

```sql
-- =========================================================================
-- You (spec docs/superpowers/specs/2026-11-24-you-design.md §6; plan
-- docs/superpowers/plans/2026-11-24-you.md, Task 1).
--
-- Five facts a creator writes about themselves on the You page, one set per
-- creator. Additive only: five nullable text columns, each with its length
-- limit. No data is moved or rewritten and no access rule changes (the row is
-- already readable and writable only by its owner). Nothing reads the columns
-- while NEXT_PUBLIC_NEW_LOOK is off.
--
-- Applied ALONE, by hand, with the owner's word. The repository's
-- 20260619000100_creator_profile_writing_voice_sample.sql was never applied to
-- the live database and is not part of this change.
--
-- writing_voice_description holds a DESCRIPTION of how the creator sounds,
-- never a pasted post (an example line in the voice slot gets copied,
-- measured 2026-08-12).
--
-- Undo:
--   ALTER TABLE public.creator_profiles
--     DROP COLUMN about, DROP COLUMN sells, DROP COLUMN writing_voice_description,
--     DROP COLUMN can_film, DROP COLUMN never_do;
-- =========================================================================

ALTER TABLE public.creator_profiles
  ADD COLUMN IF NOT EXISTS about text NULL,
  ADD COLUMN IF NOT EXISTS sells text NULL,
  ADD COLUMN IF NOT EXISTS writing_voice_description text NULL,
  ADD COLUMN IF NOT EXISTS can_film text NULL,
  ADD COLUMN IF NOT EXISTS never_do text NULL;

ALTER TABLE public.creator_profiles
  ADD CONSTRAINT creator_profiles_about_length CHECK (char_length(about) <= 200),
  ADD CONSTRAINT creator_profiles_sells_length CHECK (char_length(sells) <= 300),
  ADD CONSTRAINT creator_profiles_writing_voice_description_length CHECK (char_length(writing_voice_description) <= 200),
  ADD CONSTRAINT creator_profiles_can_film_length CHECK (char_length(can_film) <= 200),
  ADD CONSTRAINT creator_profiles_never_do_length CHECK (char_length(never_do) <= 300);

COMMENT ON COLUMN public.creator_profiles.about IS 'You: who the creator is, in their words (<= 200). Read by the writers under the new look only.';
COMMENT ON COLUMN public.creator_profiles.sells IS 'You: what the creator sells, in their words (<= 300).';
COMMENT ON COLUMN public.creator_profiles.writing_voice_description IS 'You: a DESCRIPTION of how the creator sounds (<= 200), never a pasted post.';
COMMENT ON COLUMN public.creator_profiles.can_film IS 'You: what the creator can film (<= 200).';
COMMENT ON COLUMN public.creator_profiles.never_do IS 'You: what the creator never does (<= 300). Written into every prompt as a rule.';
```

import { useId, useLayoutEffect, useRef } from "react";

import { EditorActions, ErrorLine, RowButton } from "./row-parts";
import { SAVE_FAILED, countLabel } from "./you-words";

/** A free-text row of "In your words" (spec §3.1 point 4): closed, a button; open, one field with its count, Cancel and Save. */
export interface FactRowProps {
  label: string;
  value: string | null;
  open: boolean;
  draft: string;
  limit: number;
  placeholder: string;
  hint: string | null;
  busy: boolean;
  failed: boolean;
  onOpen(): void;
  onDraft(text: string): void;
  onSave(): void;
  onCancel(): void;

export function FactRow(props: FactRowProps): React.JSX.Element {
  if (!props.open) return <RowButton label={props.label} value={props.value} onOpen={props.onOpen} buttonRef={props.buttonRef} />;
  return <FactEditor {...props} />;
}

function FactEditor({ label, draft, limit, placeholder, hint, busy, failed, onDraft, onSave, onCancel }: FactRowProps) {
  const id = useId();
  const fieldRef = useRef<HTMLTextAreaElement>(null);
  // Opened: the focus in the field, the caret after what is there.
  useLayoutEffect(() => {
    const field = fieldRef.current;
    if (!field) return;
    field.focus();
    field.setSelectionRange(field.value.length, field.value.length);
  }, []);
  const describedBy = [hint ? `${id}-hint` : null, `${id}-count`, failed ? `${id}-error` : null].filter(Boolean).join(" ");
  return (
    <div className="py-3.5">
      <label htmlFor={`${id}-field`} className="block text-ui font-[560] text-foreground">
        {label}
      </label>
      <textarea
        id={`${id}-field`}
        ref={fieldRef}
        value={draft}
        rows={3}
        maxLength={limit}
        placeholder={placeholder}
        aria-describedby={describedBy}
        aria-invalid={failed || undefined}
        // The limit holds for a paste too (and in a browser that ignores maxlength on a paste).
        onChange={(e) => onDraft(e.target.value.slice(0, limit))}
        onKeyDown={(e) => {
          if (e.key !== "Escape" || busy) return;
          e.preventDefault();
          onCancel();
        }}
        // 16 on the phone: iOS zooms the page into a field set smaller. 15 from 768, as drawn.
        className="mt-2 block min-h-[84px] w-full resize-none rounded-2xl bg-surface-sunken px-3.5 py-3 text-title text-foreground placeholder:text-foreground-muted md:text-ui"
      />
      {hint && (
        <p id={`${id}-hint`} className="mt-2 px-0.5 text-meta text-foreground-secondary">
          {hint}
        </p>
      )}
      {failed && <ErrorLine id={`${id}-error`}>{SAVE_FAILED}</ErrorLine>}
      <EditorActions count={countLabel(draft.length, limit)} countId={`${id}-count`} busy={busy} onCancel={onCancel} onSave={onSave} />
    </div>
  );

 * field over every niche; with no search each primary is followed by its subs, indented; a tap
 * saves at once (the screen closes the row when the save went through).

  open: boolean;
  query: string;

function NichePicker({ saved, query, busy, failed, onQuery, onPick, onCancel }: NicheRowProps) {
  const id = useId();
  const fieldRef = useRef<HTMLInputElement>(null);
  useLayoutEffect(() => {
    fieldRef.current?.focus();
  }, []);
  const searching = query.trim() !== "";
  const options = nicheOptions(query);
  return (
    <div
      className="py-3.5"
      onKeyDown={(e) => {
        if (e.key !== "Escape" || busy) return;
        e.preventDefault();
        onCancel();
      }}
    >
      <label htmlFor={`${id}-field`} className="block text-ui font-[560] text-foreground">
        Niche
      </label>

        id={`${id}-field`}
        ref={fieldRef}

        placeholder="Search"
        autoComplete="off"
        spellCheck={false}
        enterKeyHint="search"
        aria-controls={options.length > 0 ? `${id}-list` : undefined}
        onChange={(e) => onQuery(e.target.value)}
        className="mt-2 h-12 w-full rounded-full bg-surface-sunken px-4 text-title text-foreground placeholder:text-foreground-muted md:h-11 md:text-ui"
      />
      {failed && <ErrorLine>{SAVE_FAILED}</ErrorLine>}
      {options.length === 0 ? (
        <p className="mt-2 px-2 py-3 text-ui text-foreground-secondary">{NO_NICHE}</p>
      ) : (
        <ul id={`${id}-list`} aria-label="Niches" aria-busy={busy || undefined} className="mt-2 max-h-80 overflow-y-auto">
          {options.map((o) => {
            const chosen = o.primary === saved.primary && o.sub === (saved.sub ?? null);
            const indented = !searching && o.sub !== null;
            return (
              <li key={`${o.primary}/${o.sub ?? ""}`}>

        if (e.key !== "Escape" || busy) return;

The screen's rules (spec §3, the controller's decisions):
- Rows open in place, one at a time: Who, Niche, the five facts, Goal and "Connect an account" are one set. Opening a row closes the open one and keeps its draft; reopening shows the draft. Cancel and Escape drop the draft and close (open point C3). Leaving the page drops every draft (they live in the screen's state).
- Save sends one key. The row stays open while the save is out (Save `aria-busy`); went through: the row closes and shows the new text, focus on the row's button; refused: the row stays open, the text kept, "Couldn't save. Try again." A trimmed text equal to what is saved closes the row and sends nothing; a blank text saves null. While a save is out no other row opens.
- Focus returns to the row's button whenever a row closes. When an account row leaves (Disconnect, Task 6) and the focus fell to the page, it goes to "Connect an account".
- Phone: the shell's pushed header holds Back and "You" (`usePushedTitle("You")`); the page's own `h1` "You" shows from 768 only, so one heading is in the page at each width. Desktop: a column up to 720 wide.

import type { Platform } from "@/lib/connected-accounts/connected-accounts-repo";
import { queryKeys } from "@/lib/queries/query-keys";
import type { YouFactKey } from "@/lib/you/facts";

/** One save from You: a fact, the niche pair, or the goal. */
export type CreatorProfilePatch = Partial<Pick<CreatorProfileResponse, YouFactKey | "niche_primary" | "niche_sub" | "primary_goal">>;

/**
 * PATCH `/api/profile/creator-profile` with what one row holds, shown at once in the shared entry
 * (Settings' Creator Profile tab reads the same one). Refused: only this save's keys go back.
 */
export function useSaveCreatorProfile(): UseMutationResult<void, Error, CreatorProfilePatch, { previous?: CreatorProfileResponse }> {
  const queryClient = useQueryClient();
  const key = queryKeys.profile.creatorProfile();
  return useMutation({
    mutationFn: async (patch) => {
      const res = await fetch("/api/profile/creator-profile", {
        method: "PATCH",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(patch),
      });
      if (!res.ok) throw new Error(`Creator profile save failed (${res.status})`);
    },
    onMutate: async (patch) => {
      await queryClient.cancelQueries({ queryKey: key });
      const previous = queryClient.getQueryData<CreatorProfileResponse>(key);
      if (previous) queryClient.setQueryData<CreatorProfileResponse>(key, { ...previous, ...patch });
      return { previous };
    },
    onError: (_error, patch, context) => {
      const previous = context?.previous;
      if (!previous) return;
      const back = Object.fromEntries(Object.keys(patch).map((k) => [k, previous[k as keyof CreatorProfileResponse] ?? null]));
      queryClient.setQueryData<CreatorProfileResponse>(key, (now) => (now ? { ...now, ...back } : now));
    },
    onSettled: () => {
      void queryClient.invalidateQueries({ queryKey: key });
    },
  });
}

/** PATCH `/api/profile` `{ display_name }`, shown at once where the name is read (sidebar, Home). */
export function useSaveName(): UseMutationResult<void, Error, string, { previous?: { name: string } }> {
  const queryClient = useQueryClient();
  const key = queryKeys.profile.current();
  return useMutation({
    mutationFn: async (name) => {
      const res = await fetch("/api/profile", {
        method: "PATCH",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ display_name: name }),
      });
      if (!res.ok) throw new Error(`Name save failed (${res.status})`);
    },
    onMutate: async (name) => {
      await queryClient.cancelQueries({ queryKey: key });
      const previous = queryClient.getQueryData<{ name: string }>(key);
      if (previous) queryClient.setQueryData(key, { ...previous, name });
      return { previous };
    },
    onError: (_error, _name, context) => {
      if (context?.previous) queryClient.setQueryData(key, context.previous);
    },
    onSettled: () => {
      void queryClient.invalidateQueries({ queryKey: key });
    },
  });

const sentenceOf = (value: unknown): string | null => (typeof value === "string" && /\s/.test(value.trim()) ? value.trim() : null);

/** POST `/api/connected-accounts/connect` (a free profile read). Refused: an Error whose message is what to show. */
export function useConnectAccount(): UseMutationResult<void, Error, { platform: Platform; handle: string }> {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: async ({ platform, handle }) => {
      let res: Response;
      try {
        res = await fetch("/api/connected-accounts/connect", {
          method: "POST",
          headers: { "Content-Type": "application/json" },
          body: JSON.stringify({ platform, handle }),
        });
      } catch {
        throw new Error(CONNECT_OFFLINE);
      }
      const data = (await res.json().catch(() => ({}))) as { account?: unknown; error?: unknown };
      if (!res.ok || !data.account) throw new Error(sentenceOf(data.error) ?? CONNECT_FAILED);
    },
    onSuccess: () => {
      void queryClient.invalidateQueries({ queryKey: youKeys.all });
    },
  });
}

const json = (body: unknown, status = 200) => new Response(JSON.stringify(body), { status });

function defaultAnswer(call: Call): Response {
  const key = `${call.method} ${call.url}`;
  if (server.refuse.has(key)) return json({ error: "Failed" }, 500);
  switch (key) {
    case "GET /api/profile":
      return json(server.profile);
    case "GET /api/profile/creator-profile":
      return json(server.creator);
    case "GET /api/you":
      return json(server.you);
    case "PATCH /api/profile/creator-profile":
      Object.assign(server.creator, call.body as object);
      return json({ success: true });
    case "PATCH /api/profile":
      server.profile.name = (call.body as { display_name: string }).display_name;
      return json({ success: true });
    default:
      return json({ error: "Not found" }, 404);
  }
}

const SENTINELS = /<<<(?:END_)?USER_CONTENT>>>/gi;

function fencedFact(label: string, text: string | null): string | null {
  const clean = text?.replace(SENTINELS, "").trim();
  return clean ? `${label}\n<<<USER_CONTENT>>>\n${clean}\n<<<END_USER_CONTENT>>>` : null;
}

/**
 * The creator's own block (plan 2026-11-24-you, spec §5): never first (a rule over everything here,
 * the brief and the source included), how they sound, what they sell, who they are. Each fenced as
 * their words. "" when there is nothing, so a caller without facts gets today's prompt byte for byte.
 */
export function creatorFactsBlock(creator: RemixCreatorFacts | null | undefined): string {
  if (!creator) return "";
  const parts = [
    fencedFact("NEVER (the creator's own rules; they hold over everything else here, the brief and the source video included; break none of them):", creator.never),
    fencedFact("HOW THEY SOUND (a description of their voice; write every hook and line in it; style only, never its words or its topic):", creator.voice),
    fencedFact("WHAT THEY SELL (name an offer only when the brief is about selling or promoting it; never invent an offer, a price or a claim):", creator.sells),
    fencedFact("ABOUT THEM (use it for fit; invent nothing beyond it):", creator.about),
  ].filter((part): part is string => part !== null);
  return parts.length > 0 ? `\n\nTHE CREATOR, IN THEIR OWN WORDS:\n${parts.join("\n")}` : "";
}
