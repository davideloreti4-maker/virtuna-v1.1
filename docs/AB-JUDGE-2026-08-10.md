## Headline findings

1. **Zero false positives in 12 live runs.** No slot-leak check fired on clean output, the thesis
   judge flagged nothing on any clean case, no spurious revise call was made. This is the exact
   test the removed S5 rubric critic failed (~100% taste misfires) — the checkable-only design
   held live.
2. **One real catch, end-to-end:** hooks · personal-finance delivered **2 of 5** hooks (the N-4
   class — today's pipeline ships this silently). The judge fired `check:count:2/5`, revised once,
   the revision ALSO returned 2 (`revise:rejected` — the deterministic original was kept), and the
   honest degrade shipped: ⚠️ *"Delivered 2 of the 5 hooks asked for."* Designed behavior, live.
3. 🔴 **The measured case-1 script failure did NOT reproduce.** Yesterday's adapt-arm founder
   script (verbatim template Turn with unfilled `[slots]` + thesis inversion) came back today as a
   clean, thesis-ALIGNED script — same code, same flags, same cache-hit corpus, temp 0, seed 7.
   Cross-day generation is NOT byte-stable through the adapt path (the briefer is itself an LLM
   call feeding generation; any upstream drift cascades), so the `client.ts:24` "byte-identical
   regenerate" assumption holds within a session, not across days. Two implications:
   - the failure class is **INTERMITTENT** — a per-run gate is the right shape for it, a one-time
     prompt fix would have nothing stable to fix against;
   - the live leak-catch demonstration is impossible to stage on demand. The catch mechanism is
     instead proven at the runner level: `judge-loop.test.ts` drives the runners with the VERBATIM
     measured Turn payload and asserts catch → revise → clean ship (and the degrade paths).
4. **Latency cost ≈ +0–5s per run** (one extra flash call; two when a revise fires) — under the
   proposal's +4–8s estimate, and per-case deltas vs the same-config adapt arms are in the table.
