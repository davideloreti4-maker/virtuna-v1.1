     * Next.js metadata sitemap — Landing v1 (FOUND-10).

    export default function sitemap(): MetadataRoute.Sitemap {

      const now = new Date();
      return [

          url: `${base}/`,
          lastModified: now,
          changeFrequency: 'weekly',
          priority: 1.0,

          url: `${base}/#demo`,
          lastModified: now,
          changeFrequency: 'monthly',
          priority: 0.9,
        },
        {

          lastModified: now,
          changeFrequency: 'monthly',
          priority: 0.9,
        },
      ];
    }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| crawler request → /sitemap.xml | Public read-only — exposes site structure intentionally (SEO surface) |
| crawler request → /robots.txt | Public read-only — declares crawl policy |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-14 | I (Information Disclosure) | sitemap.ts | accept | Sitemap exposes `/`, `/#demo`, `/#pricing` — these are public landing anchors by design. Auth-gated routes (`/dashboard`, `/api`, `/auth`, `/onboarding`) deliberately excluded from sitemap and explicitly disallowed in robots. |
| T-01-15 | T (Tampering) | robots.txt obedience | accept | Malicious crawlers ignore robots.txt — it's an advisory protocol, not an access control. Defense-in-depth: auth-gated routes are protected by Supabase middleware regardless of robots.txt entries. |
| T-01-16 | E (Elevation of Privilege) | sitemap-listed routes | accept | Listed routes are anchor-only (`/#demo`, `/#pricing`) — they live on the public landing page, no privilege escalation possible. |
</threat_model>
