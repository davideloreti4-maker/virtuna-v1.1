<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user click → anchor link | href="#section-id" — same-page navigation, no external URL crosses, no JS handler involved |
| user click → /login Link | next/link to internal app route — Next.js handles routing, no untrusted input |
| dev → prod CSS pipeline | backdrop-filter via inline style bypasses Lightning CSS stripping (MOTION-04 mitigation) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-09 | T (Tampering) | backdrop-filter Tailwind class | mitigate | Inline `style={{ backdropFilter, WebkitBackdropFilter }}` applied per CLAUDE.md / PITFALLS.md Pitfall 2 — Lightning CSS strips the utility class in prod; inline survives. Verification grep gates on the inline pattern presence AND the utility absence. |
| T-01-10 | S (Spoofing) | Sign up CTA href | accept | Routes to `/login` per FOUND-08 (sign-up flow); intentional. Phase 2+ may add a dedicated /signup route, at which point this href updates — not a security concern. |
| T-01-11 | I (Information Disclosure) | nav aria-label | accept | "Landing page navigation" is public landmark text; no PII. |
| T-01-12 | D (Denial of Service) | backdrop-filter blur(12px) | mitigate | Pure GPU operation, bounded cost. No animation, no JS. Spotted browsers without backdrop-filter support (Firefox < 103) gracefully fall back to the solid rgba background (still readable). |
| T-01-13 | E (Elevation of Privilege) | client component fetching | accept | Component fetches no data; renders static markup. No XSS surface (no user-rendered content; NAV_LINKS array is `as const` typed literals). |
</threat_model>
