One click saves, zero decisions: the bookmark saves to the last-used destination (unfiled on first ever save) and confirms with the inline toast; “Change” opens the picker. Clicking a filled bookmark un-saves. The picker is also the Move to… menu on shelf cards. Saved state is real (read from the store, not local mutation state) — a card that is already saved renders filled on mount, everywhere it appears.

Plumbing contracts under this sketch (phase 1, before any UI)

  • Every save writes provenance: thread_id + ref_id = messages.id from all 11 renderers (finest stable id — block sub-items have no persisted ids).
  • No duplicates: UNIQUE index on (user_id, item_type, ref_id) once ref_id is real; existing 10 rows backfilled or grandfathered.
  • Saved state reflects the store (query, not isSuccess) → filled-on-mount, un-save from source.
  • remix saves as remix (new item_type), format either gets a writer or leaves the enum + filter.
  • Open thread ↗ = deep link /home?thread=… from thread_id; forward actions keep the 402 credit-wall handling.
  • projects table is NEW (saved_items RLS idiom, nullable project_id on saved_items) — the dead 20260526 `projects` table stays untouched.
