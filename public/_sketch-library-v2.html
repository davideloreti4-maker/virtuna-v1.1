A collection, not an inventory

Rev 3 was readable but it read as an admin table — a divider under every row, four facts middot-chained into one grey string, everything at a single weight. This is a tool for writing, so rev 4 gives the writing room: borderless rows separated by space, an icon anchor carrying type identity, and metadata cut to the two facts that matter. The palette is unchanged and deliberately monochrome — the craft has to come from spacing and type.

The default destination is inferred, not remembered. Saves now carry their thread id, so the picker can default to the project this thread already feeds and badge it — visible, not silent. “Last used” would have quietly filed a hook into a project you touched weeks ago. Clicking a filled bookmark un-saves, and saved state is read from the store, so an already-saved card renders filled on mount everywhere it appears.

What changed in rev 4

The complaint was that rev 3 didn’t feel like a shipped product. It didn’t — it had the shape of an internal tool. These are the specific causes.

Dividers on every row made it a table

A hairline under each item reads as data, and data reads as work. Rows are now separated by space and grouped by a rounded hover surface — the item under the cursor lifts, nothing else draws a line.

Four facts middot-chained into one grey string

“Hook · Contrarian, ranked 2 of 6 · Hook ideas for Q3 · 4d” is debug output. The subtitle is now source and time only; rank and archetype belong to the detail view, and the type is carried by the icon rather than repeated in words.

No type identity

Every row looked the same, so the eye had nothing to anchor to. A 34px icon tile per type gives each row a fixed left anchor and makes a mixed list legible at a glance — without spending the accent, which stays reserved for liveness.

Too tight, and one weight throughout

Content moved to 16.5px on a 56-character measure with negative tracking; padding and section spacing roughly doubled. Fewer items are visible per screen, and that is the point.

Decisions carried forward

Verified against globals.css and saved-item-card.tsx rather than recalled.

Accent is liveness, never decoration

A bookmark on every shelf row carried no information — everything on the shelf is saved. Accent now appears only on the checked box, the in-thread bookmark, and the save confirmation.

Forward actions already exist per type

“Write script →”, “Develop into hooks →”, “Test full script →” ship today in saved-item-card.tsx:46. An earlier draft replaced them with one generic button, which was a regression.

The card grid broke its own sort

CSS multicol fills column by column, so under “Recent” the second-newest sat below the newest, not beside it. Rows are ordered by construction.

Provenance is the point of phase 1

Today ref_id is written by none of the eleven renderers and thread_id by one, so all ten live saved rows are orphans with no way back to the thread that made them. Every “from …” line in this sketch depends on fixing that first.
