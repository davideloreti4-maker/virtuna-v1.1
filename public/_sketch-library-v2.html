Rows, not cards

Rev 2 was hard to read for a structural reason, not a styling one: a two-column card grid at 880px gives each item a 420px box, but most saved output is one line of text — so every hook wrapped mid-sentence and sat under three layers of chrome. Rev 3 makes the row the primitive. Full width for the content, one quiet meta line beneath it, and --muted restricted to timestamps and counts instead of doing six jobs at 10px.

One line carries the value; everything else steps down. The content sits at 15.5px cream at full width — a hook reads as a sentence, not as wrapped card text. Beneath it, one meta line in a single colour holds type, detail, source thread and age, so the eye can skip it entirely when scanning. The first row shows hover: checkbox, forward action and ⋯ occupy reserved space, so revealing them moves nothing. Only the read spends colour, on its band dot — the one sanctioned data tone. Media and measurements sit on the right: a thumbnail on the left would push the outlier's title out of line with every other row, and that shared left edge is what makes a list scannable.

The default destination is inferred, not remembered. Because saves now carry thread_id, the picker defaults to the project this thread already feeds, badged so the choice is visible rather than silent — “last used” would have quietly filed a hook into a project you touched weeks ago. No prior project for the thread means Unfiled. Clicking a filled bookmark un-saves, and saved state is read from the store, so an already-saved card renders filled on mount everywhere it appears.

Both first-run states matter more than the mature one — every current user has zero projects, and several have nothing saved. With saves but no projects, the section degrades to a single quiet row instead of an empty grid demanding setup. With nothing at all, the shipped Constellation empty state stays exactly as it is.

✦What changed, and why

Rev 3 — readability

The complaint was legibility; the cause was structural.

rev 3 The card grid was the wrong primitive.Two columns at 880px gave each item a 420px box, so a one-sentence hook wrapped across three lines and sat beneath a kicker, a segment tag and a footer. Rows. Content gets the full width and reads as a sentence; a single meta line holds everything else. Cards survive only where they earn it — the in-thread save card.
rev 3 --muted was doing six jobs.Kickers, segments, provenance, counts, section headers and chips were all #8a857c at 10.5–12.5px — most of the page was dim grey with no entry point. Muted now means timestamps, counts and the meta line only. Section headers and supporting text moved up to secondary; content is full cream.
rev 3 The type scale spanned 4px.Hero 14.5, why 12.5, kicker 10.5 — technically a hierarchy, visually a single texture. Content 15.5px, support 13.5px, meta 12.5px, with weight and colour reinforcing each step rather than size alone.
rev 3 The audit table opened the document.The first thing on screen was a wall of 12.5px grey documentation, which set the tone for everything under it. Moved here, to the end, and set in readable type. The screens now lead.

Carried forward from rev 2

Verified against globals.css and saved-item-card.tsx, not recalled.

system Accent is liveness, not decoration. The bookmark on every shelf item carried no information — everything on the shelf is saved. Dropped; Remove lives in the ⋯ menu the card already builds. Accent now appears only on the checked box and the in-thread bookmark.
system Forward actions already exist and are type-specific. “Write script →”, “Develop into hooks →”, “Test full script →” — from saved-item-card.tsx:46. An earlier draft replaced these with a generic button, which was a regression.
system Cards are darker than the page, controls lighter. #1a1a19 on #1f1f1e, controls #2c2c2b. Band tones are --color-success / warning / error.
shelf Masonry silently broke the sort. CSS multicol fills column-by-column, so under “Recent” the second-newest sat below the newest, not beside it. Rows are ordered by construction.
shelf No bulk selection. The premise is “too much output to organize”; filing one item at a time fails it. Screen 02.
shelf Search and sort had no defined scope. Screen 05 — global results, each badged with its project.

Phase 1 — plumbing, before any of this UI

Every one of these is a defect in the shipped save loop.

data Provenance on every save. thread_id + ref_id = messages.id from all 11 renderers. Today ref_id is written by none and thread_id by one, so all 10 live rows are orphans.
data No silent duplicates. UNIQUE (user_id, item_type, ref_id) once ref_id is real. Saved state reads the store rather than mutation state, so a second click un-saves instead of writing a second row.
data Type fixes. remix saves as remix, not hook. format either gets a writer or leaves the enum and the filter.
data New projects table. saved_items RLS idiom, nullable project_id. The dead 20260526 projects table stays untouched.
later Deferred past phase 1. Mobile (one column, long-press to select), ⌘K reach into saved items, drag a row onto a project, and manual ordering inside a project.
