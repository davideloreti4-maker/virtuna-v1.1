It also draws the detail view rev 4 displaced facts into but never designed.

§R5-3 — the band moved to the right rail, and this is the one change the live data forced. Rev 4 called the band dot “the read’s proof — the only colour on the shelf”. In the real store 8 of 10 saved rows carry a band: hook, idea and script snapshots all persist band, fraction and scrollQuote, not just reads. Rendered rev 4’s way that is a coloured line on almost every row; dropped, it discards the product’s core signal. On the rail it is one short string — the tone on a single word — and it lands in the same column as the outlier’s 14× baseline, so simulated and measured proof read as one family.

The rest of rev 4 is unchanged and deliberate: content at 16.5px on a 56-character measure, two subtitle facts (source + time), no dividers, hover lifting the row under the cursor, and the 34px icon tile carrying type identity without spending the accent. The lead quote is not gone — it moved into the expansion, which is the next screen.

§R5-2 — the content no longer moves. Rev 4’s note claimed the checkbox took the icon tile’s place with “same position, same footprint, no reflow”. §R5-1 — selected is no longer identical to hovered. Both were #252524 in rev 4, so a row under the cursor looked chosen. §R5-7 — the group order is now specified, and it is the pipeline. Rev 4 said a project “reads in working order” but drew only Hooks → Scripts → Read, with no Ideas group at all and a claimed 8 items against 5 drawn. §R5-6 — the bookmark had been sitting on the words. In rev 4 the in-thread card’s hook wrapped to two lines and the absolutely-positioned bookmark overlapped the first line by 14px, straight through “are”. The line now reserves that column. Everything else here is rev 4 intact: the default destination is inferred from this thread and badged, never “last used”, which would silently file a hook into a project you touched weeks ago.

Clicking a filled bookmark un-saves. Saved state is read from the store keyed on the item’s identity, not from the mutation’s success flag — which is why an already-saved card renders filled the moment it mounts, and why a second click can no longer write a second row.

What changed in rev 5, and how each was found

Rev 4 was signed off, so nothing here is a matter of taste — every item is something that was measurably wrong, plus the one screen rev 4 promised and did not draw.

§R5-1 Selected looked exactly like hovered

Both states painted #252524. Selection now uses a faint accent wash with a 1px accent edge; hover keeps the neutral lift. Found by reading the two rules side by side.

§R5-2 Entering selection shifted the content 16px

An 18px checkbox replaced a 34px tile, so the body’s left edge moved 173px → 157px — while rev 4’s own note claimed “same position, same footprint, no reflow”. The checkbox now centres in a fixed 34px slot. Found by measuring getBoundingClientRect() on both screens rather than trusting the note.

§R5-3 The band is not read-only data

Rev 4 reserved the band dot for reads, “the only colour on the page”. The live store says 8 of 10 rows have a band — hooks, ideas and scripts persist it too. It moved to the right rail as one string with the tone on one word, sharing the column with the outlier’s measured multiplier. Found by querying the database, not the sketch.

§R5-4 The detail view was displaced into, never drawn

Rev 4’s justification for the two-fact subtitle was that rank and archetype “belong to the detail view”. No such view existed, and nothing said what clicking a row did. Screen 02 is that view: expanded in place, so filing never loses your position.

§R5-5 “Remove” was ambiguous and undressed

Identical chrome to the primary, adjacent to it, and silent about whether it removed from the project or deleted the save. Now “Unsave 3”, error tone, divided off past Cancel.

§R5-6 The bookmark overlapped the hook by 14px

.tcard .line set max-width:none against an absolutely positioned bookmark, so the first of two lines ran under it. The line reserves the column now.

§R5-7 Group order inside a project was unspecified

“Working order” was asserted; the drawing showed Hooks → Scripts → Read, omitted Ideas, and claimed 8 items while drawing 5. Fixed as Outliers → Ideas → Hooks → Scripts → Reads, empty groups omitted. Manual ordering considered and dropped.

§R5-8 Drifting labels and counts that did not add up

The crumb read the literal word “Project”; the shelf said “Reads” where the project said “READ”; the header claimed 14 saved against parts summing to 19. Name, plurals and arithmetic all reconcile now.

§R5-9 The page is 880px, not 820px

Rev 4 drew an 820px column. The real surface is PageShell at 880px — measured live, signed in. The route’s loading.tsx was a third value again, max-w-5xl (1024px), so the skeleton jumped on hydration.

Decisions carried forward from rev 4

Unchanged, and re-verified against globals.css and the live surface.

Rows, not a card grid

Confirmed live and worse than described: four columns inside the 880px shell gives each card 196px, so every hook truncates mid-sentence and the segment chips degrade to “Sleep-…”, “T…”, “St…”. The multicol also breaks its own sort — reading the live shelf left-to-right gives Jul 28 → Jun 26 → Jun 24 → Jun 21 → Jun 29.

Accent is liveness and interactive state

No bookmark on a shelf row — everything on the shelf is saved by definition. The accent appears on the checked box, the selection wash, the in-thread bookmark and the save confirmation. Nowhere else.

Forward actions already exist per type

“Write script →”, “Develop into hooks →”, “Test full script →” ship today in saved-item-card.tsx. Replacing them with one generic button was a regression an earlier draft made; the expansion now shows the typed action and the thread link instead of falling through to a generic push to /home.

Projects: manual, single-membership, no tags, no nesting

Outputs only. Threads stay in the sidebar; every saved row deep-links back to the thread that made it. Built as a new library_projects table — the 2020s-era projects table still holds two live “My Boards” rows defaulted to the retired coral, and is not revived.
